# Публікація лендінгу

Стек: **Cloudflare Workers** (хостинг + обробник форми, безкоштовно) + **Resend** (пошта, безкоштовно до 3000 листів/міс).
Разом виходить 0 грн/міс, SSL і CDN включені.

---

## 1. Домен

Купіть домен у зоні **`.com.ua`** — реєструється вільно, виглядає локально й серйозно.
Назву беріть під ключ, за яким крутитимете рекламу, наприклад:

- `kompozytni-rukavy.com.ua`
- `kompozytni-shlanhy.com.ua`

Уникайте `.site`, `.online`, `.xyz` — для промислового B2B виглядають несолідно.
Зона `.ua` без торгової марки недоступна.

Після покупки **переведіть домен на Cloudflare** (реєстратор → замінити NS-сервери на ті,
що видасть Cloudflare). Це потрібно, щоб і хостинг, і DNS-записи для пошти були в одному місці.

---

## 2. Хостинг: Cloudflare Workers

Проєкт — це **Worker зі статичними ассетами**: `public/` віддається як статика,
а `src/index.js` обробляє єдиний динамічний маршрут `POST /api/lead`.
Конфігурація — у `wrangler.jsonc`.

> **Важливо.** Не заливайте папку через «Upload assets» без `wrangler.jsonc`.
> Тоді Cloudflare створить Worker, у якому є **лише статика**, і в Settings
> з'явиться напис *«Variables cannot be added to a Worker that only has static assets»* —
> ключі для пошти додати буде нікуди, і форма не працюватиме.

### 2.1. Залити файли

1. Зареєструйтеся на [dash.cloudflare.com](https://dash.cloudflare.com).
2. Задеплойте з командного рядка з кореня цієї папки:

   ```bash
   npx wrangler deploy
   ```

   Перший запуск попросить залогінитись у браузері. Назва проєкту береться
   з поля `name` у `wrangler.jsonc` — змініть, якщо треба інша.
3. Сайт відкриється на технічній адресі виду `oil-hose.<ваш-субдомен>.workers.dev`.
   Перевірте, що все на місці.

Оновлення в майбутньому — та сама команда `npx wrangler deploy`.

### 2.1.1. Локальний запуск

```bash
npx wrangler dev
```

Підніме сайт на `http://localhost:8788` разом з обробником форми.

## 2.2. Підключити власний домен

Порядок кроків важливий: спочатку домен має стати зоною Cloudflare, і лише потім
прив'язуємо його до Worker'а.

### Крок 1. Додати домен як зону Cloudflare

1. У дашборді: **Add a domain** (кнопка вгорі або **Account Home → Add a domain**).
2. Введіть домен **без `www`** — наприклад `kompozytni-rukavy.com.ua`.
3. Оберіть план **Free**.
4. Cloudflare просканує наявні DNS-записи. У щойно купленого домену їх не буде — це нормально.
5. На екрані з'являться **два NS-сервери** виду `ana.ns.cloudflare.com` і `bob.ns.cloudflare.com`.
   Випишіть їх — у кожного акаунта вони свої.

### Крок 2. Замінити NS-сервери в реєстратора

Потрібен розділ **«Сервери імен» / NS** — це **не** редактор DNS-записів.
Дві різні сторінки, їх легко переплутати.

1. Видаліть NS-сервери реєстратора, які стоять за замовчуванням
   (у припаркованих доменів це щось на кшталт `parked1.uadns.com`, `parked2.uadns.com`).
2. Впишіть два сервери від Cloudflare.
3. Збережіть.

Зміна для зони `.com.ua` проходить через реєстр hostmaster.ua — зазвичай від 15 хвилин
до 2 годин, зрідка до доби. Коли все підхопиться, статус зони в Cloudflare зміниться
на **Active** і прийде лист.

**Далі не продовжуйте, поки зона не стала Active.**

### Крок 2.1. Прибрати записи припаркованого домену

DNS-записи, які були в реєстратора, переносити вручну **не треба** — вони вели на його
заглушку. Але Cloudflare міг скопіювати їх собі під час додавання домену.

Коли зона стала Active, відкрийте **DNS → Records** і видаліть:

| Запис | Чому |
|---|---|
| `A` для `@` (може бути кілька однакових) | ведуть на заглушку реєстратора — перекриють лендінг |
| `A` для `www` | те саме |
| `A` для `mail`, `CNAME` для `ftp` | службові записи хостингу реєстратора, не потрібні |
| `MX` | **видаляйте лише якщо** на цьому домені не потрібна поштова скринька |

Про `MX`: для роботи лендінгу він не потрібен. Форма шле листи на адреси філій, а Resend
для **відправки** вимагає тільки TXT-записи SPF і DKIM. `MX` потрібен, тільки якщо ви хочете
**отримувати** пошту на адресу цього домену.

Якщо не почистити `A`-записи, крок Custom domains конфліктуватиме з наявним записом,
а на домені відкриватиметься заглушка замість сайту.

### Крок 3. Прив'язати домен до проєкту Pages

1. **Workers & Pages → ваш проєкт → Domains → Add → Custom domain**.
2. Введіть домен без `www` → **Continue** → **Activate domain**.
3. Cloudflare **сам створить потрібний DNS-запис**. Нічого додавати вручну не треба.
4. Повторіть те саме для `www.ваш-домен.com.ua` — щоб обидві версії відкривались.

Статус стане **Active** за кілька хвилин; SSL-сертифікат випускається автоматично
(інколи до 15 хвилин). Поки він випускається, браузер може лаятись на сертифікат — це минеться.

> **Не створюйте CNAME вручну** до того, як додали домен через екран Custom domains.
> Тоді сайт віддаватиме помилку 522.

### Крок 4. Обрати головну версію адреси

Треба, щоб сайт відкривався за однією канонічною адресою, а друга на неї перенаправляла.
Для реклами це важливо: у Google Ads final URL має вести на кінцеву адресу без зайвих редиректів.

**Rules → Redirect Rules → Create rule**:

| Поле | Значення |
|---|---|
| Rule name | `www to apex` |
| If — Field | Hostname |
| Operator | equals |
| Value | `www.ваш-домен.com.ua` |
| Then | Dynamic redirect |
| Expression | `concat("https://ваш-домен.com.ua", http.request.uri.path)` |
| Status code | 301 |
| Preserve query string | увімкнено ✅ |

Галочка **Preserve query string** обов'язкова — без неї загубляться UTM-мітки й `gclid`,
і реклама перестане коректно відстежувати конверсії.

### Крок 5. Увімкнути HTTPS

- **SSL/TLS → Overview** → режим **Full (strict)**.
- **SSL/TLS → Edge Certificates** → **Always Use HTTPS** = On.
- Там же **Automatic HTTPS Rewrites** = On.

### Крок 6. Перевірити

- [ ] `https://ваш-домен.com.ua` відкриває лендінг
- [ ] `http://` автоматично перекидає на `https://`
- [ ] `www.` перекидає на основну адресу
- [ ] посилання з міткою `?utm_source=test` не губить мітку після редиректу

### Якщо щось не працює

| Симптом | Причина |
|---|---|
| Помилка **522** | CNAME створили вручну, не через екран Custom domains. Видаліть запис і пройдіть Крок 3 заново |
| Зона довго не стає Active | NS ще не оновились у реєстрі `.ua`. Перевірте, що в реєстратора **видалені** старі NS |
| Сертифікат не випускається | На домені є **CAA-записи**, які забороняють Cloudflare видавати сертифікат. Буває у доменів з історією. Додайте CAA для `letsencrypt.org`, `pki.goog`, `ssl.com` або приберіть CAA зовсім |
| Нескінченний редирект | Режим SSL стоїть **Flexible** замість **Full (strict)** |

## 3. Пошта: Resend

Обробник форми (`src/index.js`) шле заявки через Resend.

1. Зареєструйтеся на [resend.com](https://resend.com), **Domains → Add Domain** → ваш домен.
2. Resend покаже DNS-записи (SPF, DKIM, DMARC). Додайте їх у Cloudflare: **DNS → Records**.
   **Це критично** — без них листи падатимуть у спам. Це найчастіша причина ситуації
   «форма наче працює, а заявок немає».

   Для записів типу TXT і MX проксі не застосовується — вони автоматично будуть DNS-only.
   Якщо Resend дає CNAME, переконайтеся, що хмарка сіра (**DNS only**), а не помаранчева,
   інакше верифікація не пройде.
3. **API Keys → Create API Key**, скопіюйте ключ.
4. Додайте змінні. `RESEND_API_KEY` — це секрет, тому краще через CLI:

   ```bash
   npx wrangler secret put RESEND_API_KEY
   ```

   Решту — у дашборді: **Workers & Pages → ваш проєкт → Settings → Variables and Secrets**:

   | Змінна | Значення |
   |---|---|
   | `RESEND_API_KEY` | ключ із Resend (секрет) |
   | `MAIL_FROM` | `Лендінг <lead@ваш-домен.com.ua>` |
   | `MAIL_BCC` | *(необов'язково)* адреса для копії всіх заявок |

   Якщо замість полів бачите *«Variables cannot be added to a Worker that only has static assets»* —
   деплой пішов без `wrangler.jsonc` і в ньому нема скрипта. Передеплойте через `npx wrangler deploy`.

5. Після додавання змінних у дашборді зробіть **Deploy** ще раз, інакше Worker їх не побачить.
   Змінні, додані через `wrangler secret put`, застосовуються одразу.

## 4. Аналітика і конверсії

1. У `public/index.html` замініть `GTM-XXXXXXX` на свій ID контейнера — **у двох місцях**
   (у `<script>` в `<head>` і в `<noscript>` на початку `<body>`).
2. У Google Tag Manager створіть тригери на події `dataLayer`:

   | Подія | Що означає | Конверсія в Google Ads |
   |---|---|---|
   | `generate_lead` | форму успішно надіслано | основна, цінність 1 |
   | `phone_click` | клік по номеру телефону | другорядна |
   | `form_error` | помилка валідації | не конверсія, для діагностики |

3. Підключіть **Consent Mode v2** — без нього по трафіку з ЄС будуть прогалини в даних.
4. UTM-мітки й `gclid` збираються з URL автоматично і приходять у листі із заявкою.

## 5. Перед запуском реклами

- [ ] **Увімкнено автопродовження домену** в кабінеті реєстратора.
      За замовчуванням воно часто вимкнене. Прострочений домен = зупинена кампанія,
      а відновлення коштує в рази дорожче за продовження
- [ ] Домен зареєстровано на компанію та корпоративну пошту, а не на особистий акаунт
- [ ] Сайт відкривається на своєму домені по HTTPS
- [ ] Тестова заявка дійшла на пошту потрібної філії й **не потрапила у спам**
- [ ] У листі видно UTM-мітки
- [ ] GTM-контейнер підставлено, конверсія `generate_lead` спрацьовує (перевірити в Preview)
- [ ] Логотип: покладіть `logo-tubes-international.svg` у папку `images/`
      (зараз як запасний варіант підвантажується з основного сайту)
- [ ] Створіть на домені сторінку політики конфіденційності й змініть посилання
      біля чекбокса згоди у формі — Google вимагає її при зборі персональних даних
- [ ] Узгодьте право на використання рендера рукава (`images/composite-hose-cutaway.*`) —
      це матеріал виробника Dantec
- [ ] Дайте сайту побути в мережі день-два до створення кампанії: Google перевіряє
      посадкову сторінку, нові домени іноді довше проходять модерацію
- [ ] Дані компанії в акаунті Google Ads мають збігатися з тими, що на сайті

## Індексація

Сторінка закрита від пошуку (`noindex`) — щоб не конкурувати з розділом композитних
шлангів на основному сайті. `robots.txt` при цьому **дозволяє** сканування: інакше Google
не побачить сам `noindex`, а краулер Google Ads не зможе перевірити посадкову.

Якщо згодом захочете органічний трафік — змініть у `public/index.html` рядок
`<meta name="robots" content="noindex, follow">` на `index, follow`.

  index.html                    сторінка
